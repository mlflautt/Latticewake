# Reference synth research

This directory preserves external reference material that informs Latticewake's
product thinking. These sources are not implementation specifications, bundled
assets, or endorsements. Latticewake remains a terrain-centred instrument with
its own visual language and portable C++ engine.

## Sources and retained lessons

| Source | Type | Factual scope | Latticewake-relevant lesson | Explicit non-goal |
| --- | --- | --- | --- | --- |
| `abyss2-manual-2.pdf` | User manual | Abyss 2's Gradient, Tone Colour, palette, modulation, sequencer, and expressive-input workflows. | Present prepared timbral landmarks as a navigable continuum; normalize different controller inputs into semantic performance dimensions. | Copying Abyss's spectral engine, horizontal Gradient, or preset-centric product identity. |
| `hyperion-user-guide.pdf` | User guide | Hyperion's modular sound-design and routing interface. | Make per-note, per-lane, per-engine, and global scope visible when it matters. | Turning the Terrain Stage into an unrestricted node-and-cable editor. |
| `myth-manual.pdf` | User manual | Myth's central sound object, bounded module sections, and variation workflows. | Keep a directly playable central object and make bounded variation an explicit action. | Copying Myth modules, re-synthesis implementation, or visual design. |
| `novum-manual.pdf` | User manual | Novum's separation of timbral, temporal, and articulation-oriented sound controls. | Preserve independent Surface, Traversal, and Articulation components so they can be exchanged without destructive rewrites. | Adopting Novum's decomposition engine or making sample processing a prerequisite for terrain play. |
| `Terrain_Synth-User-Manual-v0.13.pdf` | User manual | Conductive Labs Terrain Synth's performance controls and terrain-oriented hardware interaction. | Keep gesture, path, activity, and direct performance legible before deep editing. | Reproducing its fixed hardware architecture or interaction layout. |
| `Terrain_Synth_UserGuide-3.pdf` | User guide | A second Terrain Synth operational reference. | Treat saved musical worlds and immediate audition controls as first-class instrument behavior. | Treating Latticewake as a hardware emulation or copying its factory workflow. |
| `Synth Plugins First-Principles Report.md` | Secondary research report | A comparative analysis of modern software-synth interface, DSP, modulation, and expression paradigms. | Use perceptual visual metaphors, bounded macro structure, prepared offline analysis, and semantic expression mappings. | Treating its mixed-source technical claims as sufficient implementation evidence; primary sources and experiments remain required. |

## How to use this library

Use a source to inform a documented product decision, then record the decision
and its limits in the relevant cycle brief or handoff. Do not extract or ship
third-party artwork, audio, presets, code, or text from these materials. The
source files retain their original filenames for stable citations.
