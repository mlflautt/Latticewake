# **Latticewake Stage UI Architecture, Visual Design, and 2026 macOS Validation Plan**

To build and validate Latticewake’s Stage on macOS in late 2026, the most reliable architecture pairs a custom NSView backed directly by CAMetalLayer and CAMetalDisplayLink for the terrain canvas with a SwiftUI shell for import/comparison controls and synthetic accessibility elements1. Unlike MTKView, which developer postmortems show can stretch stale drawable contents between redraws during live window resizing, a directly managed CAMetalLayer keeps the imported fractal image, interpreted field, luminous contours, traversal path, sampling point, and active voices locked inside one pixel-registered coordinate space while isolating the real-time C++ audio kernel behind immutable lock-free terrain snapshots3. Avoiding commercial synthesizer skeuomorphism and unrestricted modular node graphs, this design relies on luminance-separated perceptual layering, registered superposition for visual comparison, and situated gesture feedforward so the instrument remains legible without a permanent instruction wall6.  
For development and validation as of November 2026, verification must be split between hosted automation and physical Apple hardware. Following GitHub’s retirement of the macos-14 runner image on November 2, 2026, standard hosted Apple silicon runners (macos-15, macos-26, and xcode-27) execute inside virtualized guests (VirtualMac2,1) with AppleParavirtGPU rather than bare-metal Apple silicon GPUs, and they lack physical audio interfaces, MIDI hardware, or Logic Pro test benches10. Hosted CI can establish universal compilation, Swift–C++ interoperability, sanitizer cleanliness, auval schema compliance, Developer ID signing, and notarization, whereas ProMotion 120 Hz pacing, live-resize visual smoothness, Core Audio hardware latency, Logic Pro AUv3 hosting stability, and perceptual audio–visual quality require a target Mac and human listener14.

## **Stage Rendering Stack Comparison**

Selecting the Stage graphics layer involves evaluating image rendering, contour density, live window resizing, coordinate alignment, VoiceOver visibility, Reduced Motion compliance, ProMotion refresh capping, and stale-frame dropping. SwiftUI Canvas (macOS 12.0+) provides immediate-mode drawing via GraphicsContext and exposes a ColorRenderingMode option (documented in SwiftUI developer guides as including .extendedLinear for high-headroom colors), making it straightforward for moderate 2D overlays19. However, Canvas ties redraw timing to SwiftUI’s view invalidation and layout cycle rather than explicit Metal drawable pacing, and complex GraphicsContext closures can hitch when driven continuously21. Core Graphics (CGContext) produces crisp CPU vector contours and integrates directly with NSAccessibilityProtocol (macOS 10.10+), yet software rasterizing dense contour lines over high-DPI fractal textures at 60–120 Hz risks CPU bottlenecks and thermal frame drops22.  
Metal provides the GPU throughput required for real-time iso-contours and multi-layer blending, but MTKView introduces specific macOS resizing hazards. Across developer reports on Stack Overflow, technical postmortems (thume.ca, June 2019), and cross-platform engine changelogs (sokol, egui), MTKView exhibits intermittent frames of stretched old content during live window drag—even when presentsWithTransaction is enabled—and updating MTKView.drawableSize inside resize callbacks risks recursive layout loops3. Subclassing NSView directly with a CAMetalLayer (wantsLayer \= true, layerContentsRedrawPolicy \= .duringViewResize, layerContentsPlacement \= .topLeft, autoresizingMask \= \[.layerWidthSizable, .layerHeightSizable\], and needsDisplayOnBoundsChange \= true) eliminates live-resize edge judder3. Coupling that layer with CAMetalDisplayLink (macOS 14.0+) adds CAFrameRateRange caps, preferredFrameLatency control, and clean skipping of present() whenever no new snapshot has arrived1.

## **Component Boundaries, Coordinate Conventions, and Audio Isolation**

Wave terrain synthesis—introduced by Mitsuhashi (1982) and developed for multidimensional polyphonic expression and visual workflows by James (2005, 2012, 2015\) and Zabetian (2018)—generates pitch from the periodic orbit rate over a 2D surface z \= f(x, y) while shaping timbre and amplitude from the topography along that path32. Because audio-rate terrain lookup executes far faster than visual or control updates36, Latticewake should reject an unrestricted node-graph paradigm and enforce five fixed-responsibility boundaries with one-way immutable publication to the DSP thread.

| Component | Ownership & Runtime | Responsibilities | Isolation Constraint |
| :---- | :---- | :---- | :---- |
| Asset & Field Importer | Swift / AppKit (Utility Queue) | Decodes fractal images, computes interpreted height/gradient fields, builds preview assets, and manages security-scoped bookmarks | Asynchronous only; never touches the audio render thread5 |
| Staging Coordinator | Swift (@MainActor) | Owns Surface A, Surface B, and transient Import Preview state; handles Compare toggles and atomic "Replace A", "Replace B", or "Cancel" actions | Modifying or previewing surfaces leaves Traversal and Articulation parameters untouched |
| Immutable Snapshot Bridge | C++20 / Swift C++ Interop | Publishes immutable TerrainSnapshot buffers (float32 height grid and metadata) and reads lock-free VisualTelemetry slots | Audio reads immutable pointers via std::atomic; Stage drops intermediate telemetry5 |
| Real-Time DSP Kernel | C++20 (\[\[clang::nonblocking\]\]) | Runs polyphonic voice orbits, 2D surface interpolation, A/B morph crossfading, and held-note articulation shaping | Zero locks, zero heap allocations, zero Objective-C/Swift runtime calls5 |
| Stage View & Chrome | NSView \+ CAMetalLayer \+ SwiftUI | Composites registered source, interpreted field, iso-contours, traversal orbit, sampling cursor, and voice glyphs plus accessibility tree | Never blocks audio; skips present() when telemetry generation equals last presented frame14 |

Every visual and sonic layer inside Latticewake’s Stage must evaluate against one normalized terrain domain (u, v) in \[0, 1\]^2, with (0.5, 0.5) at the terrain center and consistent Y-axis orientation across Metal texture sampling, CPU/GPU field interpolation, and AppKit pointer hit-testing. When the Stage resizes, the renderer derives a single aspect-preserving float4x4 viewport transform mapping \[0, 1\]^2 into Metal drawable pixels and provides the exact inverse transform to convert pointer events back into (u, v). Because the source fractal image, interpreted DSP lookup grid, iso-contour shaders, traversal orbit, and pointer-owned notes all share this matrix, resizing the window or switching comparison modes never misaligns a contour line from a fractal ridge or drifts a clicked note away from the terrain height being heard.  
To guarantee that audio never waits for UI work, the Staging Coordinator treats loaded terrains as immutable snapshots. Importing an image builds a new candidate buffer off the audio thread for visual preview; only when the artist explicitly commits **Replace A** or **Replace B** does the bridge atomically swap the pointer or double-buffered slot read by the DSP kernel5, while preserving existing Traversal orbit parameters and Articulation settings. Clicking **Cancel** discards the preview buffer with zero DSP side effects. Conversely, the audio thread writes active voice coordinates (u\_i, v\_i), sample height, and orbit phase into a pre-allocated single-producer, single-consumer (SPSC) lock-free structure5. Inside CAMetalDisplayLink's metalDisplayLink(\_:needsUpdate:) callback, the renderer reads only the latest completed telemetry generation inside an @autoreleasepool, skips intermediate snapshots if the main thread fell behind, avoids calling present() if no state changed, and drops strong references to CAMetalDrawable immediately after commit()14.

## **Visual States, Perceptual Layering, and Situated Interaction**

Keeping the original fractal image legible beneath luminous contours requires separating perceptual channels rather than raising opacity indiscriminately. Colin Ware’s visual perception research (*Information Visualization: Perception for Design*, 2004–2020; *Visual Thinking for Design*, 2010\) establishes that the human visual system depends on the **luminance channel** for spatial structure, edges, and contours, whereas chromatic hue carries much lower spatial acuity8. If a high-contrast fractal image and contour lines compete across identical mid-to-high luminance values, contours fragment visually or obscure the underlying geometry. As an engineering design application of Ware’s findings and GenoREC’s non-occluding overlay rules (cited in 2020 comparative layout research42), the Metal fragment shader should compress the fractal image into a dark-to-mid luminance pedestal (for example, remapping background luminance to roughly 10–45% of display headroom) while reserving crisp, narrow-stroke, high-luminance accents—optionally using .extendedLinear headroom—for iso-contours, traversal curves, and active voice markers8.  
For inspecting source imagery alongside field interpretation and comparing Surface A with Surface B, Gleicher et al. (2011) categorize comparative visualization into **juxtaposition** (separate space or temporal A/B toggling), **superposition** (shared space), and **explicit encoding** (difference or contour overlays)6. Empirical evaluation of equally georeferenced maps (2015) shows that transparent superposition in a shared coordinate space improves spatial comparison relative to side-by-side juxtaposition7. Latticewake’s Stage should therefore default to registered superposition—source image pedestal plus translucent interpreted field plus luminous contours—while offering quick temporal toggling and a registered split-wipe curtain for direct pixel-to-height inspection.

| State Dimension | Recommended Visible States | Visual Encoding & Rationale |
| :---- | :---- | :---- |
| Layer Identity | Surface A active, Surface B active, Morphed A/B blend | High-discriminability hue tags drawn from Ware’s palette (e.g., cool cyan for A, warm amber for B)8 applied strictly to frame badges, contour tinting, and morph endpoints without tinting raw source pixels |
| Morph State | Continuous crossfade (m in \[0, 1\]) | Live dual-weight readout (A 70% / B 30%) paired with real-time interpolated iso-contours so the displayed topography matches the blended DSP lookup surface |
| Import Preview | Idle vs. Staging Preview (Previewing \[filename\]) | Registered translucent overlay or split-wipe curtain with a floating commit bar (**Replace A**, **Replace B**, **Cancel**); Traversal and Articulation controls display a subtle locked-safe state to signal immunity |
| Asset Status | Resolved, Missing/Offline, Default Fallback | **Resolved** displays filename, pixel size, and field resolution; **Missing** renders diagonal hatched bounds and an amber badge (Missing Source — Using Cached Field or Relink…) within the registered frame |
| Comparison Mode | Source-Only, Interpretation, Contours-Only, Superposed (Default), Split-Wipe | Single-key switch within the shared (u, v) frame6: Source-Only lifts the luminance pedestal; Interpretation renders field elevation; Superposed balances image and contours |

To teach keyboard play, pointer-owned notes, held-note shaping, and traversal clearly without a permanent text wall, the interface should apply Wensveen, Djajadiningrat, and Overbeeke’s (2000) principles of **natural coupling** and **inherent feedforward**, alongside situated **signifiers**9. Before click-down, hovering the pointer across the Stage reveals a minimal reticle and localized terrain elevation readout at (u, v), signaling playability and previewing surface height before sound is triggered9. When the artist presses and drags to hold a **pointer-owned note**, an anchored voice ring binds to the cursor with a crisp vector tether and localized contour highlight; dragging moves the sampling anchor across (u, v), while an expanding radial fill arc encodes held-note shaping depth—mirroring dynamic fill-wheel signifiers tested in HCI nanointeraction studies9.  
By contrast, **keyboard and MIDI notes** render as untethered voice nodes distributed along the active **traversal** orbit with compact voice-index pips, visually distinguishing autonomous key-driven voices from pointer-owned voices without textual labels. The traversal path itself renders as a continuous luminous curve, and the active **sampling point** appears as a high-contrast marker advancing at a visually legible sub-rate phase cue (never attempting raw audio-rate flicker). Any first-run micro-hint (such as a single-line ephemeral cue on pointer hover or preview entry) dismisses automatically after first interaction so the Stage stays clean during performance.

## **Accessibility and Interaction Testing**

Because CAMetalLayer renders an opaque GPU buffer, VoiceOver and keyboard users cannot inspect Stage layers unless Latticewake projects a semantic accessibility tree aligned with the shared viewport transform. Wrap the AppKit Metal view in SwiftUI’s .accessibilityChildren(children:) (macOS 12.0+) or implement NSAccessibilityProtocol.accessibilityChildren() (macOS 10.10+) to expose synthetic accessibility elements for the Stage summary (active Surface A/B names, morph percentage, comparison mode, active voice count), keyboard-adjustable sampling anchor controls, missing-asset relink actions, and native SwiftUI buttons for **Replace A**, **Replace B**, and **Cancel** during import preview2.  
When NSWorkspace.shared.accessibilityDisplayShouldReduceMotion is enabled, the renderer must disable animated orbit trails, pulsing glows, and moving phase strobes, substituting static trajectory geometry, crisp directional tangent arrows, and step-updated position markers while clamping CAMetalDisplayLink.preferredFrameRateRange to 30 Hz or on-demand updates1. Automated UI tests should invoke XCUIApplication.performAccessibilityAudit(for:\_:) (macOS 14.0+) across idle, comparison, missing-asset, and import-preview states to verify element descriptions, hit regions, contrast, element detection, and parent-child loop integrity48. Because developer reports on Apple Developer Forums (October 2026, Xcode 27.1/27.2) document false-positive .elementDetection (nil element) warnings on SwiftUI modal sheets and offscreen contrast quirks, automated audits must be paired with manual Accessibility Inspector and VoiceOver verification48. Additionally, because Apple announced macOS 27.3 notarization limits restricting the accessibility entitlement strictly to assistive technologies, Latticewake must use only standard NSAccessibility and SwiftUI accessibility APIs without requesting Accessibility privacy permissions51.

## **Verified Facts, Recommendations, and Unresolved Choices**

**Verified Facts (as of November 2026\)**:

> * CADisplayLink and CAMetalDisplayLink are supported on macOS 14.0+ with CAFrameRateRange and ProMotion refresh rates up to 120 Hz on supported MacBook Pro and Studio Display XDR displays1.  
> * Developer reports and OSS changelogs document live-resize stretching in MTKView on macOS, whereas a custom NSView with CAMetalLayer (.duringViewResize and .topLeft placement) eliminates resize judder3.  
> * An independent CAMetalDisplayLink benchmark on macOS measured a 3-refresh (49.8 ms) windowed lead at 60 Hz and a 5-refresh (41.5 ms) lead at 120 Hz, sustaining 94–99% of the 120 Hz panel rate while skipping present() on unchanged frames14.  
> * GitHub Actions retired macos-14 on November 2, 2026; standard arm64 runners (macos-15, macos-26, xcode-27) run on 3 vCPU (M1) / 7 GB RAM virtualized guests with AppleParavirtGPU, and macos-26 arm64 runners can raise SubmissionsIgnored faults if a process exits while Metal GPU work remains in flight10.  
> * xcodebuild supports ASan, TSan, and UBSan (with ASan requiring Hardware Memory Tagging disabled in Xcode 26.1+), while upstream LLVM Clang 20.1.0+ provides RealtimeSanitizer (-fsanitize=realtime)37.  
> * MetricKit diagnostic classes (MXDiagnosticPayload, MXCrashDiagnostic) are deprecated in macOS 27.2/27.3 SDKs in favor of DiagnosticReport71.  
> * HCI and visualization literature establishes luminance primacy for contour perception (Ware, 2004–2020), registered superposition advantages for map/spatial comparison (Gleicher et al., 2011; 2015 evaluation), and natural coupling / feedforward signifiers (Wensveen et al., 2000; 2019 nanointeraction study)6.

**Engineering Recommendations**:

> * Implement the Stage as an AppKit NSView \+ CAMetalLayer \+ CAMetalDisplayLink renderer wrapped in SwiftUI for import/comparison controls and .accessibilityChildren(children:) semantic projection1.  
> * Isolate .interoperabilityMode(.Cxx) inside one SwiftPM bridge target and maintain a dedicated CMake \+ LLVM Clang CI lane for RTSan validation of the pure C++ DSP kernel37.  
> * Target a native macOS AUv3 host container and extension (rather than Mac Catalyst) and automate Developer ID distribution with xcrun notarytool (.p8 API key) and xcrun stapler18.

**Unresolved Choices Requiring Prototyping**:

> * Whether to compute iso-contours via screen-space fragment shaders (zero CPU geometry prep) or precomputed marching-squares vector paths cached per Surface (analytical stroke width and direct accessibility regions).  
> * Whether Source-vs.-Interpretation comparison should center on a draggable split-wipe curtain, a momentary peek shortcut, or continuous opacity crossfading inside the registered Stage.  
> * Whether Xcode 27’s bundled AppleClang exposes \-fsanitize=realtime directly or requires retaining a separate Homebrew/LLVM Clang toolchain in CI67.  
> * Whether to set the minimum deployment target at macOS 14.0+ (CAMetalDisplayLink and performAccessibilityAudit baseline) or macOS 15.0+ / 26.0+ (simplifying Core Audio Process Tap and DiagnosticReport adoption)1.  
> * Whether to attach a self-hosted bare-metal Mac mini runner (or third-party M4/M5 Pro runner) for automated Metal and Logic Pro regression gates beyond standard GitHub-hosted PR checks13.
